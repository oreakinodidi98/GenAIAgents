# Security Policy

## Supported Versions

This repository is a learning/demo workspace and is actively maintained on the `main` branch.
Security fixes are applied to `main` only.

| Version / Branch | Supported |
| --- | --- |
| `main` (latest) | :white_check_mark: |
| Tagged snapshots / historical commits | :x: |
| Local forks / private modifications | :x: |

Notes:
- No backports are provided for older snapshots.
- To receive security fixes, update to the latest `main` branch.

## Reporting a Vulnerability

If you discover a security vulnerability, please report it privately.

Preferred reporting channel:
- Use GitHub Private Vulnerability Reporting in the repository Security tab.

If private reporting is unavailable, open a confidential report through repository maintainers and avoid posting exploit details in public issues.

Please include:
- A clear description of the issue and potential impact.
- Affected file(s), component(s), and environment details.
- Reproduction steps or proof-of-concept (minimal and safe).
- Any suggested remediation, if available.

What to expect:
- Initial acknowledgment within 3 business days.
- Triage/update within 7 business days.
- If accepted, maintainers will work on a fix and coordinate disclosure timing.
- If declined, maintainers will provide a brief rationale.

Disclosure guidance:
- Do not publish the vulnerability publicly until a fix or mitigation is available.
- After remediation, maintainers may publish a security advisory and credit the reporter (if requested).

Thank you for helping improve the security of this project.
